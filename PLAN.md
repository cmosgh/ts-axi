# ts-axi plan

AXI CLI (https://axi.md) for TypeScript/JavaScript code: a queryable symbol index whose purpose is `impact` - an agent reviewing a change learns which other parts of the code it affects without reading dozens of files. Read-only: no lint, no refactor, no rename. Vocabulary: `GLOSSARY.md`. Engine choice: `docs/adr/0001`; monorepo scope: `docs/adr/0002`; `--ref`: `docs/adr/0003`.

Built like `../bb-axi`: same `args.ts` / `render.ts` / `errors.ts` / `version.ts`, `runAxiCli` from `axi-sdk-js`, TOON output, generated `skills/ts-axi/SKILL.md`.

## Engine (ADR 0001)

- Single dependency `typescript` 6.x (JS line). Never native deps.
- **Syntactic path** (`outline`, `def`, home): `ts.createSourceFile` on candidate files only. No tsconfig required. Target: < 1 s.
- **Semantic path** (`refs`, `callers`, `impact`): `ts.createLanguageService` over the Project. Uses `findReferences`, `getDefinitionAndBoundSpan`, `provideCallHierarchyIncomingCalls`, `getQuickInfoAtPosition`, `getNavigationTree`.
- Project discovery: nearest `tsconfig.json` walking up from cwd (or from the target file's directory when a path is given); `-P <tsconfig>` overrides; `.ts-axi.json` `project` key as a per-repo default. No tsconfig anywhere → implicit project (`allowJs`, `strict: false`, every `.ts/.tsx/.js/.jsx/.mjs/.cjs` below the repo root minus `node_modules`, `dist`, `build`, `.git`) and a `warning: no tsconfig.json found - implicit project` line.
- Languages: `.ts .tsx .js .jsx .mts .cts .mjs .cjs`. No Vue/Svelte SFC.
- Excluded from results always: `node_modules`, `.d.ts` outside the project, files not in the Project.
- Cold start per command in v1; every semantic command prints `elapsed_ms`. Daemon / disk cache, vitest/jest config auto-detect = phase 2.
- A `-P` / `.ts-axi.json` / nearest tsconfig that has `references` and no files of its own after parsing is expanded to the union of its referenced configs (recursively, deduplicated; options of the first, `types` merged); output says `tsconfig: <path> (<n> referenced configs)`.

### Workspaces (ADR 0002)

No configuration, no new files in the analysed repo. `src/workspace.ts` detects from the repo root, most specific first, keeping every signal: `nx` (`nx.json`; projects = `project.json` dirs, or legacy `workspace.json`), `pnpm-workspaces` (`pnpm-workspace.yaml` `packages:` globs), `npm-workspaces` (`package.json` `workspaces`), `tsconfig-references` (root tsconfig with `references` and no `files`/`include`), `single`, `implicit`. It resolves projects `{name, dir, tsconfigs}` (tsconfig roles lib/app/spec/e2e/root by name, then by `include`), `paths` aliases (`tsconfig.base.json`, else root `tsconfig.json`, relative `extends` followed) and workspace packages (`package.json` `name`, `exports` subpaths, `main`/`types`, `src/index`).

File listing (`src/walk.ts`, used by every walk): inside git one `git ls-files -z --cached --others --exclude-standard` from the root (nested repos/worktrees and gitignored dirs never appear), minus `node_modules`, `dist`, `build`, `coverage`, `tmp`, `.nx`, `.angular`, `.claude`, `.cursor`, `.idea`, `.vscode` segments. Outside git: an fs walk with the same skip list plus any directory below the root holding a `.git` entry. A linked worktree (`.git` file) is its own root. Several Declarations of a searched name are ordered by path depth, then alphabetically.

Scope: with no `-P` and no `.ts-axi.json` `project`, a multi-project workspace (or an implicit project of more than 3000 files) is one file set for name lookup, and each semantic command builds its program from a subgraph:

- Importer index (`src/importers.ts`, syntactic): every workspace source file read once; regex extraction of `import`/`export ... from`, side-effect imports, `require()`, `import()`, `vi.mock()`/`jest.mock()`; specifiers resolved through relative paths (`.js` → `.ts`, `index.*`), `paths` aliases, workspace package names (exports subpaths, `dist` → `src` best effort); unresolvable ones ignored. Cap 50k files / 3 s → `scope_partial: true` + a help line.
- Seeds: the declaring file(s) for `refs`/`callers` (a use position first finds its Declaration in a one-file program), the touched files for `impact` (deleted and renamed-away paths still resolve so their importers count), the file itself for `def` on a use.
- Hops: `refs`/`callers` 1, `impact` 2; a re-export (`export * from`, `export { x } from`) costs no hop, so importers of a barrel that re-exports the seed are direct importers.
- Program: root names = seeds + importers (TypeScript resolves their own imports); options = the seed's nearest tsconfig (for a references shell, the referenced config that includes the seed, `types` merged across them), minus emit/layout options (`composite`, `rootDir`, `outDir`, ...), plus the workspace `paths` when the config has none, plus `paths` for workspace package names so they resolve to sources. `diagnostics` counts the touched files only.
- Output: `scope: nx workspace - 23 of 9612 files (seeds 1; importers 22)` on semantic commands; the home view prints `workspace: nx (14 projects)` and `tsconfig: nearest per file - workspace scope`.
- `-P` keeps one explicit project. `refs`/`callers` with `refs_total: 0` under `-P` in a workspace list `found_outside_project[n]{file,line}` (importers outside the Project whose text names the Symbol) + a hint to run without `-P`.
- Type errors in the analysed project never block anything: `diagnostics: <n>` when > 0 on the semantic path, with a help line naming `--diagnostics`, which lists `diagnostic_rows[n]{file,line,code,message}` (at most 20).

### `--ref <rev>` (ADR 0003)

`def`, `refs`, `callers`, `outline` answer from the git tree of `<rev>` instead of the working tree. Every repo read goes through `sourceFs()` (`src/fs.ts`); `--ref` swaps `diskFs` for `gitTreeFs` (`src/gittree.ts`): rev resolved once to a SHA, one `ls-tree -r -z`, blobs by batched `cat-file --batch` (2000 per call, prefetched per listing), `GIT_NO_LAZY_FETCH=1`, submodules skipped, symlinks followed inside the tree. Paths outside the root and `node_modules` stay on disk (`node_modules: working tree (not in git)` when read); `.ts-axi.json` stays on disk. Output starts with `ref: <rev> @ <short sha>`; hints keep `--ref`. A file not in the rev: `file not in <rev>: <path>` (exit 2). Unknown rev, missing blob: `GIT_ERROR`. `impact`, `config`, `setup` reject `--ref` (impact hint: `ts-axi impact <rev>...HEAD`). Guards: `test/ref.test.ts` (poisoned working tree = clean checkout) and `test/ref-leak.test.ts` (no disk read below the root).

| `def <target>` | syntactic | Declarations of a Symbol by name. Exactly 1 match → detail: `file, line, kind, exported, signature` + body fenced with absolute file line numbers (first 60 lines, `--full` lifts, `(truncated, N lines total)` marker). >1 match → compact list `matches[n]{file,line,kind,exported,signature}` + help on how to narrow. 0 → `matches: 0`, `did_you_mean[≤5]` (names within edit distance 2 / same prefix among Declarations of the Project), exit 0; when the name still occurs whole-word in Project files (an untyped property set up elsewhere), help says `Run ts-axi refs <name> --grep for <k> textual matches`, and `refs <name> --grep` lists them as `unresolved[n]{file,line,context}` with `note: no declaration found - textual matches only`. |
| `refs <target>` | semantic | References of ONE Symbol, grouped by file: `symbol, kind, declared_at, refs_total, files, tests` then `refs[n]{file,line,context}` (context ≤ 100 chars, trimmed), at most 50 location lines (`--limit`, max 500), `truncated: true` + exact total when cut. `--kind calls` is the same as `callers`. Rows in Test files sort last; without `--tests` they leave `refs[n]` for `test_refs[n]{file,count}` (biggest first, at most 20) + a `--tests` hint (`refs_total`, `files`, `tests` still count them). A `property` target prints `same_name_members: n (Other.prop)` (names up to 5, else the count): same-named properties of other types that are neither via nor implementations - an entity field mapped into a DTO is no Reference. |
| `callers <target>` | semantic | Call-hierarchy incoming calls of a function-like Symbol, same shape as `refs` plus `caller` (the enclosing function/method name per row). The call hierarchy also reports any `x.method` property access; only a call target counts (the callee of a call, `new`, tagged template, decorator, JSX tag, or `fn.call/apply/bind(...)`, through parens, `!`, `as`, `satisfies`). The rest print as `not_calls: n` with a `refs` hint and never seed `--depth` levels. `--depth N` (1..3): levels > 1 print `file:count` per caller, no locations. |
| `outline <file>` | syntactic | Top-level Declarations in source order, class members nested: `decls[n]{line,kind,name,exported,signature}`. `--exports` keeps exported only. Multiple files allowed (glob). |
| `impact [<git-range> \| -]` | semantic | See below. |
| `anchor [<git-range> \| - \| --staged] <file:line[-end]>...` | syntactic | See below. |
| `config` | - | `config` prints effective settings with their source (`default`, `.ts-axi.json`, `flag`); `config set <key> <value> [--replace]`, `config unset <key>` write `.ts-axi.json` at the repo root (idempotent, no `--confirm`). Keys: `test-globs` (repeatable/additive unless `--replace`), `project`. |

Global flags: `--json` (decoded TOON payload, like mysql-axi), `--help`/`-h` per command, `-v/--version` (fast path), `-P <tsconfig>` on every command that may go semantic, `--ref <rev>` on `def`, `refs`, `callers`, `outline`.

### Targets

- Name: `save`, `User.save` (member of class/interface/enum/namespace), `--kind function|class|method|property|variable|interface|type|enum|enum-member|namespace|state`, `--in <glob>` (restrict to files), `--exported`, `--fuzzy` (substring, case-insensitive).
- Position: `path:line[:col]` - the identifier at that position. Col omitted → the declaration that starts the line: among the names the line declares (indexed Declarations, parameters, binding elements, function-valued properties), one nested in another's declaration (a function's parameters, an object member, a constructor's parameter properties) ranks after it; siblings left (`const a = 1, b = 2`) list them, like an ambiguous name. A line that declares nothing: its one distinct identifier, else the list.
- `refs` / `callers` need exactly one Symbol: an ambiguous name prints the candidate Declarations (`matches[n]`) + `help` showing the disambiguated forms (`ts-axi refs src/a.ts:42` or `--in src/models`), exit 0, no analysis run.
- Ambiguity lists (`def`, `refs`, `callers`) show at most 20 rows, shallowest path first, then `matches_total` and `truncated: true`. The help is computed from all matches, each line saying how many it keeps: the two largest subtrees below their common directory (`--in`), each kind present (`--kind`), `Parent.member` when the matches have distinct parents, `--exported` when it cuts the list.

### `impact`

Input, all normalised to `{ file → changed line ranges (after), file → changed line ranges (before), status added|modified|deleted|renamed }`:

- `impact` → working tree vs `HEAD` (staged + unstaged); `impact --staged` → index vs HEAD.
- `impact <range>` → any `git diff` range: `main...HEAD`, `abc123`, `v1..v2`.
- `impact -` → unified diff on stdin (e.g. `bb-axi pr diff 42 --raw | ts-axi impact -`). Paths are taken relative to the repo root (`a/`, `b/` prefixes stripped).
- `git` via `child_process` only. Not a git repo and no stdin diff → `GIT_ERROR` (exit 1) with the `impact -` alternative.

Before-version: `git show <base>:<path>` read in memory for touched files only; parsed syntactically to find the before-Declarations and Signatures. With stdin input and no repo, the before Signature is rebuilt from the `-` lines of the hunk when the whole declaration header is present; otherwise the change class is `modified`.

Per touched file: changed line ranges map to the innermost enclosing Declaration (top-level, class member or nested declaration). Lines outside any Declaration (imports, side-effect statements) are reported as `file-level` changes of that file, one row per file, no references.

Change classes (GLOSSARY): `added | removed | signature | body | type | modified`. Signature = declaration text without body, whitespace-normalised, comments stripped; a variable, class field or enum member's initializer is its body (`const x: T` is the Signature), a registration's DI array is part of its Signature.

### Legacy JavaScript

Script-style code (AngularJS, Meteor, CommonJS, IIFE modules) keeps its functions below the top level, where no Declaration used to exist and `impact` could only say `file_level`. `collectDeclarations` adds **nested declarations** (GLOSSARY) in the same single syntactic pass, in JS and TS files alike, walking only module-level statements, `if` blocks and IIFE bodies (never ordinary function bodies): `<recv>.controller|service|factory|directive|filter|component|run|config|provider('Name', fn | [...deps, fn])` → `function Name` (parent = the verb, signature `controller Name(params)`; `this.x = function` in controller/service/provider bodies and the object a factory returns become `Name.x`), object-literal methods of `Meteor.methods`, `Template.x.helpers|events`, `module.exports`, `const x = {...}`, `Foo.prototype.bar =` / `Foo.bar =` / `exports.x =` functions, and IIFE top-level functions. `fn` may be an identifier (`.directive('fancyBox', fancyBox)`, `['$uibModal', fancyBox]`): a function declaration or function-valued variable of that name among the statements of the call's scope, before or after the call (hoisting), with `fancyBox.$inject = [...]` compared like a DI array; the registration's `namePos` is the function's own name, which links the two Declarations (`registrationOf`), so `refs` on either (or on the registration line) reports templates and the note under the registered name, and the registration's members replace the function's own. **Escaping objects**: the function-valued properties and shorthand methods of an object literal a module- or IIFE-level function returns at its top level (`return {...}` or `=> ({...})`), of `exports.x = {...}`, `this.x = {...}` (holder `Owner.x`) and `export default {...}` (holder `default`) are methods of that holder (`makeItemDeps.canReadItem`); data properties are not Declarations. **Members by identifier** (John Papa style): in a constructor-like body (controller/service/provider callback, capitalised constructor) a top-level `var|let|const <id> = this` makes `<id>` stand for `this`; `<this|id>.x = <identifier>`, and an identifier or shorthand property of a returned object (`return { a: a, b }`, `var service = { a, b }; return service`, plus `service.c = c`), name a function declaration or function-valued variable of the same body (hoisted). That function becomes the member `Owner.x` with its own span, Signature (`function loadItem(id)`) and `namePos`, so `def`, `impact` and a `path:line` target on the function line resolve to it, and once only (the function is not a second Declaration). The aliasing name (`self.loadItem`, the property key) is recorded as `aliasPos`/`aliasLine`: a line target there resolves to the member (two on one line ask for a column), and the Reference on that line counts as part of the Declaration, not as a use or a textual match. Identifiers that name no nested function (`self.http = $http`, data) are not members. DI uses (`itemStore.loadItem()` in an injecting controller) stay textual: Project-wide count plus `--grep` rows. String-registered names have no identifier: `namePos` is the function, `nameless: true`, a `path:line` target on that line resolves to it, and `refs` says their uses are textual and offers `--grep` (whole-word matches in Project files and templates).

- **States** (GLOSSARY): `.state('name', {...})`, `.state({ name, ... })` and `.when('/path', {...})` calls chained on an identifier named `$stateProvider` / `$routeProvider` (`$urlRouterProvider.otherwise()` ignored) become kind `state`, `states.<name>` (`routes.<path>`), nameless, `namePos` = the object literal, signature `state <name> (url <url>)` (plain-literal options such as `templateUrl` / `controller` compared on a hidden line, like a DI array). Function-valued properties (a DI array's function included) become methods `states.<name>.<key>`, object-valued ones recurse up to three levels (`resolve.x`, `views.main.controller`): an edit in a `.then` inside a `resolve` maps to the innermost one. These chains are recognised at module level, at the top level of `.config` / `.run` callback bodies and of any function (declaration or variable) that takes a `$stateProvider` / `$routeProvider` parameter (`.config(routes)`), never deeper. Everything below a state object (`resolve.x`, `onEnter`, `controller`, `views.*`) is flagged `injected`: the router calls it or injects it by name into the state's own component, so it gets no textual count and no `any`-access blind spots (`isTextualCandidate` / `isBlindSpotCandidate`); the state object itself keeps the project-wide count.
- **State arrays**: an object literal is also a State when it is an element of an array literal that initialises a module- or IIFE-level `const/let/var` (`export const` included), is assigned to `module.exports` / `exports.x` / `module.exports.x`, is `export default`, or is the receiver or an argument of `.concat(...)` in one of those places (`module.exports = [{...}].concat(childStates)`), and it has a `name` plus at least one of `url resolve component controller template templateUrl views abstract`. Same Declaration as the `.state()` path (one `stateFromObject`): `namePos` and start = the object literal, so `def path:<line of {>` finds it. Name: a string literal as is; a template literal with each `${id}` replaced by the value of a same-file string const `id` (any depth, up to three hops; declared twice = unresolved), else `*` (`` `${parentName}.done` `` → `states.*.done`); an identifier (or shorthand `{ name }`) → its const value, else the identifier text. `` .state({ name: `...` }) `` uses the same resolution. Not followed: arrays built elsewhere and imported, `push`/spread, arrays inside function bodies.
- **Bindings**: `scope` / `bindToController` keys of the object a directive returns, and a component's `bindings`, become `property` Declarations `<directive>.<key>`; the signature is `key: '='`, so a binding-mode change is a `signature` Change.
- **Template usages** (`src/templates.ts`): for a directive or component, one of its bindings, a controller or a filter, one regex pass over every template file of the repo root (`*.html *.htm *.ejs *.hbs *.njk *.pug`, git listing), at most one usage per line: `<kebab` or a `kebab` / `data-kebab` / `x-kebab` attribute (closing tags are not usages); a binding's `kebab-attr` only when the tag it sits in (back to the last `<`, no `>` between) carries the directive; `ng-controller="Name"`; `| name` (not `||`). `refs` / `callers` print `templates: <n> usages in <m> files` after `textual:`; `refs --grep` merges the usages into `unresolved` (one row per file:line), and the `--grep` hint counts both. `impact` adds a `templates` column (`-` for other rows) when any changed Symbol has a template form; a Change with template usages is never `local_only`; template files of the diff that use a changed Symbol go to `template_changes[n]{file,symbols}` (`symbols` joined by `; `), the others stay in `skipped`. `tests` counts source files only. A column over a block for the same reason as `textual`; `unresolved` over a separate `templates[n]` block because `templates` already names the count and `--grep` is the one switch for textual rows.

### Plain JavaScript packages

- Implicit compiler options stay `module: ESNext` + `moduleResolution: Bundler` (one set for ESM with `"type": "module"` and CommonJS): a sweep over Bundler, Node10, Node16, NodeNext and Preserve resolved every specifier of both sample packages to the same files (`require('..')` → the directory's `main`/`index.js` included) and gave the same References. The misses came from elsewhere, handled in the LanguageServiceHost (`resolveModuleNameLiterals`, whole-project and subgraph programs alike):
  - **`.d.ts` twins**: TypeScript tries `.ts/.tsx/.d.ts` before `.js`, so `import x from './index.js'` bound to `index.d.ts`. A resolved `.d.ts` whose same-basename `.js/.jsx/.mjs/.cjs` is a Project source file resolves to that file (`isExternalLibraryImport: false`). Belt and braces: `findReferences` / call hierarchy on a Declaration in `x.js` also query the same-named top-level Declaration of `x.d.ts` when that file is in the program, merged and deduplicated by position.
  - **CommonJS shims**: the binder makes no alias of `module.exports = require('./lib/x')` (it does of `module.exports = name`), so `require('..')` through such an `index.js` never reached the function. A resolved Project file whose only statement (besides directives) is that assignment (`exports = module.exports = require()` too) resolves to the inner specifier, up to 3 hops.
- **Textual safety net**: for `refs`/`callers`/`impact` on a Symbol declared in a JS file, a nameless one, or any Symbol of an implicit Project, a whole-word count of the name over the Project's files (lines declaring that name excluded) prints as `textual: <n> matches in <m> files` after `refs_total`. When `n > refs_total` and some matches sit on no Reference line, `help` says `Run ... --grep for the <k> textual matches the checker cannot resolve (untyped JavaScript)` where `k` is exactly the number of rows `--grep` lists (positions on Reference lines are not counted, so the hint never promises rows that do not appear). `impact` counts matches outside the change set against `refs_outside`; a Change with such matches is never `local_only`, and the `changed` table gains a `textual` column (`-` for typed rows) only when some row has them. **Needle**: `textualNeedle` is the last segment of the qualified name, except for a `state`/route, whose needle is the full dotted name without `states.`/`routes.`, matched as a whole token (no `[A-Za-z0-9_$.]` on either side, so `ui-sref="a.b"` counts and `a.b.c` does not match `a.b`) in Project files and in `.html` and the other `--grep` template files; a state name still holding `*` has no needle and prints no `textual:` line. **Scope**: an `injected` Declaration (a state's `resolve.x`, `onEnter`, `controller`) is never counted, textually matched or checked for blind spots; a plain local (`isPlainLocal`: `exported: false`, not nameless, no parent, and its name is a parameter, a binding inside a function or IIFE, or a top-level binding of an ES module, or of a CommonJS file whose top-level `module.exports` / `exports.x` assignments never hand it out as a value - `{ a, b: c }`, `= d`) is counted in its declaring file only and prints `textual: <n> matches in this file`; an object property (indexed or not), a top-level binding of a plain script (a global) and anything a CommonJS export names count Project-wide; the `impact` `textual` column and the `--grep` rows use the same scope (in `impact --grep`, a name changed both as a plain local and as anything else, or as plain locals of two files, is searched Project-wide). Members (`app.render`, `Foo.prototype.x`) keep the Project-wide count even when their holder is not exported, because the holder may escape through `module.exports = app`. A column over a separate `textual_only[n]` block: the count sits next to `refs_outside` on the same row, nothing to cross-reference by symbol name, and the typical table stays as narrow as before.

Output order: `signature` and `removed` that are exported first, then `type`, then `added`, then `body`, then `modified`, then `file-level`. Within a class, exported = the class is exported and the member is not `private`/`#private`.

Per Change: `symbol, kind, change, exported, refs_total, refs_outside, via, files, tests` + `refs[n]{file,line,context}` (only References outside the change set, grouped by file, global budget 50 rows across the whole report, `--limit` to 500; when cut, each symbol keeps its first rows and `truncated` says how many are missing). Changes whose every Reference is inside the change set are collapsed into one line `local_only: <n> (name, name, ...)` (max 10 names, then `+k`). `tests` = count of Test files among the referencing files; `tests: 0` on an exported `signature`/`body` change is a finding the agent should see.

Via References (GLOSSARY): the LanguageService resolves a class member through the interface or base member it implements, so `findReferences` also returns the other implementations. `src/references.ts` splits its groups: the queried Symbol's group is direct; a group of a member it implements/overrides is **via** (minus Declarations and `super.x` calls); a group of a member that implements/overrides it is an **Implementation** (its Declaration) or via (its uses); any other class/interface member group is a sibling and dropped; non-member groups (import aliases) stay direct. The call hierarchy is split by matching its call spans against the same buckets. `refs_*`, `files`, `tests` count direct References only; `via` = via References outside the change set (0 when none); `--via` adds them to `refs[n]` with a `via` column (the member named, `-` for direct) and `help` suggests it when any `via` > 0. `refs`/`callers` print `via_interface: n (Iface.member)`, `via_implementations: n (Impl.member)` and `implementations: n` (rows with `--implementations`). A `signature` Change of a member that implements/overrides another adds `notes[n]{symbol,note}` (`implements Iface.member`): the contract may break.

`--depth N` (1..3): for N > 1 add `callers_depth2[n]{file,count}` etc. (counts only).

`--size` (opt-in in text and `--json` alike) adds `size{files,hunks,lines_added,lines_removed,patch_chars,exported_signature_changes,removed_symbols}` from the parsed diff and the classification, with no extra git call. For a git source `hunks` is counted at zero context (impact diffs with `-U0`; nearby changes merge into one hunk at `-U3`), for `-` as given; untracked files count as added (one hunk each) and are not in `patch_chars` (the length of the diff text). Routing rules on these numbers stay in the caller.

`blind_spots[n]{symbol,reason}`: the checker found a property access on `any`/`unknown` with the changed member's name, an element access with a string literal of that name, or the Symbol is reached by `export *` that the checker could not follow. Never a textual fallback by default. `--grep` adds `unresolved[n]{file,line,context}`: textual whole-word occurrences of changed names that are not References (max 20 rows).

Miss fallback (`def`, `refs`, `callers` name targets that match no indexed Declaration, never `--fuzzy`): source files the tsconfig leaves out (the repo listing minus the Project, `.d.ts` and `node_modules` dropped; empty for a workspace or implicit Project, which already list every file) and the Project files are prefiltered on the name, then parsed alone (at most 2000; `not_searched` counts the rest). It finds the indexed shapes in left-out files (`project: outside (not in tsconfig.json | own tsconfig x | Deno x/deno.json)`) and function, class and plain `const/let/var` Declarations nested in a function or block body anywhere (`local_to: <enclosing function>`; parameters, destructured and loop bindings excluded). One hit: `def` shows it; `refs`/`callers` run a local through the normal position path, and answer a left-out one with `matches: 0`, `outside_project: n matches in m files (dirs)`, its textual rows and the `path:line:col` hint. Several: `matches[n]{at,kind,name,where}` + position hints. A position target in a left-out file adds that file and the left-out files naming the identifier to the Project's roots. `textualScan` (the `--grep` miss rows) and `outline <glob>` cover left-out files too (`note: n files outside the Project`).

`refs`/`callers` with `matches: 0` under an explicit `-P` or `.ts-axi.json` `project`: a bounded syntactic walk of the repo root outside the Project (same caps as the home view, stops at 3 hits) prints `found_outside_project[n]{file,line}` and a `hint` naming the nearest tsconfig of the first hit, instead of suggesting `--fuzzy`. In `impact`, Test files skipped as `not in the Project` (a `tsconfig.lib.json`/`tsconfig.app.json` that excludes specs) add a help line naming the sibling tsconfig (`tsconfig.json`, else `tsconfig.spec.json`, preferring one that includes them).

### `anchor`

`ts-axi anchor [<git-range> | - | --staged] <file:line[-end]>... [--side new|old] [--context <n>] [--fields ...]` checks review-comment Anchors (GLOSSARY): an inline comment only lands on a line the diff shows.

- **Diff source**: as `impact` (none = working tree vs HEAD with untracked files as added, `--staged`, a range, `-`). Git sources run `git diff -U<n> --no-color --no-ext-diff -M` with `--context 3` by default (what Bitbucket and GitHub show); `-` uses the diff as given and rejects `--context`. `bb-axi pr diff <id> --raw | ts-axi anchor - ...` is the PR review path. The first positional is the source when it is `-` or does not look like `path:line`; a non-anchor after it is a usage error whose hint puts the source first; `path:line:col` is rejected.
- **Sides**: `--side new` (default) checks after-file lines (added or context); `--side old` before-file lines (removed or context), matched by the old path of a rename. Paths are repo-relative (a cwd-relative path from a subdirectory is tried too).
- **Validity**: every line of the anchor is shown in one hunk (`in_diff`) and lies within the line count of that side (`in_file`; text read with `git show <rev>:<path>`, the working tree for none / `-` / a single-rev range, the index for `--staged`). `ok` = both.
- **Rows**: `anchors[n]{anchor,ok,reason,symbol}`; `--fields in_diff,in_file,nearest,change,other_line` (or `all`). `reason` is `-` when ok, else `not in diff - nearest <a-b>`, `past end of file (<n> lines)`, `removed line - use --side old` (new side; the old side removed that line number), `added line - use --side new` (the reverse), `crosses hunk boundary - hunk <a-b>`, `file added - use --side new`, `file deleted - use --side old`, `file not in diff`, `binary`. `nearest` is the closest hunk's shown lines on that side (`114-120`, what the comment can move to; the help names the full `file:a-b`). `symbol` is `qualifiedName#kind` of the smallest Declaration spanning the anchor (syntactic: `collectDeclarations`, no LanguageService), `file_level` outside any, `-` for non-TS/JS files or unknown text. `change` is that Symbol's `classifyFile` class in this diff, else `-`. `other_line` is the context line's number on the other side.
- **Stdin consistency**: the checkout must be the diff's after side; a file whose hunks do not reverse-apply to it has unknown text (`symbol: -`, `in_file: -`) and the output warns with a count.
- **Exit codes**: 0 every anchor ok, 3 `ANCHOR_INVALID` when any is not (the output still prints in full), 2 usage, 1 git.
- No `--ref` (anchors are about a diff) and no `-P` (no Project is built).

Test files: default globs `**/*.test.*`, `**/*.spec.*`, `**/__tests__/**`, `**/test/**`, `**/tests/**`, `**/e2e/**`, `**/spec/**`, `**/test.*`, `**/*_test.*`; `.ts-axi.json` `testGlobs` is added to the defaults (or replaces them with `"testGlobsReplace": true`); `--test-glob <glob>` (repeatable) adds at run time. The home view shows `test_globs: <n>` and `test_files: <n>` so a wrong rule is visible.

### `.ts-axi.json`

```json
{ "testGlobs": ["**/*.it.ts", "packages/*/qa/**"], "testGlobsReplace": false, "project": "tsconfig.app.json" }
```

Located at the git root (or cwd when not a repo). Unknown keys → `VALIDATION_ERROR` naming the valid set.

## Output rules

- TOON via `block()`, `helpBlock()`, `out()`; raw code only between `---` fences with absolute line numbers, format `  42 | const x = 1` (right-aligned number, ` | ` separator).
- `--json`: the same payload as an object; fenced text becomes a string field.
- Numbers stay numbers. Paths are repo-root-relative with `/`. No commas, colons or double quotes in TOON string values where avoidable (signatures may contain them: they are quoted by the encoder, accepted).
- Every result ends with a `help` block of concrete next commands with real values filled in (`ts-axi refs src/a.ts:42`, `ts-axi def User.save`).
- Empty states are definitive: `matches: 0`, `refs_total: 0`, `changes: 0`, exit 0.
- Exit codes: 0 ok/empty, 2 usage or validation, 1 internal failure (`UNKNOWN`) or git failure (`GIT_ERROR`), 3 `anchor` with an anchor that is not commentable (`ANCHOR_INVALID`).
